========================================================
  Module absences — installation
========================================================

1. CORRIGER LE GATE DE VALIDATION
----------------------------------
La regle confirmee est : seuls le DIRECTEUR et l'ADMINISTRATEUR
valident une absence. Le chef de service ne valide PAS.

Dans app/Enums/RoleUtilisateur.php, corriger :

    public function peutValiderAbsence(): bool
    {
        return $this->estResponsable();   // directeur + administrateur
    }

(la version precedente incluait le chef de service, c'est faux)


2. ROUTES
---------
Dans routes/web.php, groupe middleware('auth') :

    // Tout le monde peut deposer une demande.
    Route::view('/absences', 'absences.index')->name('absences.index');

    // Seuls directeur et administrateur valident.
    Route::view('/absences/validation', 'absences.validation')
        ->middleware('can:valider-absence')
        ->name('absences.validation');

ATTENTION a l'ordre : /absences/validation doit etre declaree
APRES /absences, mais avant toute route /absences/{parametre}.


3. NAVIGATION
-------------
Dans layouts/navigation.blade.php, apres le lien Evenements
(bureau ET mobile) :

    <x-nav-link :href="route('absences.index')" :active="request()->routeIs('absences.*')">
        Absences
    </x-nav-link>


4. STOCKAGE DES JUSTIFICATIFS
------------------------------
Les justificatifs sont enregistres dans storage/app/public.
Creer le lien symbolique une seule fois :

    php artisan storage:link

Sans cela, les liens "Justificatif" renverront une 404.


5. LIEN DEPUIS LA PAGE ABSENCES
--------------------------------
Pour que le directeur atteigne l'ecran de validation, ajouter
dans resources/views/absences/index.blade.php, dans le x-slot header :

    @can('valider-absence')
        <a href="{{ route('absences.validation') }}" class="lien-action">
            Demandes a valider
        </a>
    @endcan


6. CE QU'IL FAUT TESTER
------------------------
  a. En compte agent : deposer une demande de conge de 3 jours
     -> l'apercu doit annoncer 3 jours ouvres (week-ends exclus)
     -> le solde affiche reste a 30 tant que ce n'est pas valide

  b. Deposer une PERMISSION de 3 jours
     -> refus immediat : plafond de 2 jours par demande

  c. En compte administrateur : valider la demande de conge
     -> le solde de l'agent passe a 27

  d. LE TEST QUI COMPTE : creer un evenement dont la couverture
     tombe pendant ce conge valide, puis ouvrir la modale Equipe
     -> l'agent en conge doit apparaitre dans "Indisponibles ce jour-la"

Le point (d) est la demonstration que les deux modules de
l'application se parlent. C'est l'argument central de la
soutenance : une seule base, une seule regle de disponibilite.


A CONFIRMER AVEC LA DIRECTION
------------------------------
Les JOURS FERIES malgaches ne sont pas decomptes : seuls les
samedis et dimanches sont exclus du calcul. Si la direction
les decompte aussi, il faudra une table jours_feries.
